### 最初の紹介をどう成立させるか

教室には「授業外で本人が困った一言を練習へつなげる補助ツール」として提案する。教材制作、毎日の督促、生徒管理、個人情報リスト提供を依頼せず、担当者の短い試用と、希望者への案内1回をお願いする。紹介元側の動機は、生活での実践支援を追加負担なく提供できることという仮説で、提案への返答で確認する。

初回の候補・連絡先・紹介用ref・送信文は `segment-marketing-experiment-2026-07.md` と `beachhead-outreach-templates.md` にある。英語はシンガポールのトロピックス/SLI、中国語は香港Practical Mandarin/上海中天を起点にする。学校だけに偏らず、次の候補群には日本人生活コミュニティの管理者、現地生活サポートや留学・ワーホリ支援の担当者も含め、紹介しやすさと実利用を比較する。新規候補はまだ選定・連絡済みではない。

2026-09-07に[トロピックス公式](https://www.tropics.sg/)の在住日本人・生活英語という対象と、[Practical Mandarinの日本人向け公式案内](https://www.practicalmandarin.com/index.php?a=lists&c=index&catid=29&m=content)の香港生活者・家族向け対象を再確認した。適合する紹介先になり得るという判断で、紹介同意や提携実績はない。上海等の接続未確認地域は担当者の通常回線で確認してから利用者配信を相談する。

紹介物は、共通コピー「現地で訳したフレーズを、次は自分の言葉に。」、生活上の一言を使った短いデモ、転載できる案内文、紹介元ごとのURLの4点とする。既存告知画像は再利用候補だが、旧画面・自動保存の説明が残っていないか確認する。Xは公式情報・使い方・改善履歴・許諾済み事例を確認できる補助媒体として扱う。

### 毎週の確認と結果別の変更

週2回を目安に、紹介先への進行と利用結果をまとめて確認する。毎日広範にSNS検索する運用には戻さない。個別の返信期限や不具合は随時対応し、通常の集計は既存ログを再利用する。この頻度は提案で、予定済みタスクの設定変更は本依頼では行わない。

| 起きていること | 次に変えること |
|---|---|
| 紹介先が返答しない・配信しない | 窓口と対象適合、件名、相手の利点、依頼の負担を確認。次の適合先で1点ずつ試す |
| 配信されたが訪問されない | 配信実態・到達人数・見出し・生活場面・リンクを確認。母数不明を反応ゼロにしない |
| 訪問されるが翻訳されない | 初回の理解、入力する一言の想起、言語選択、接続・表示速度を確認 |
| 翻訳されるが保存されない | 覚えたい場面か、訳が合っているか、追加ボタンが分かるかを確認。翻訳だけで用が済んだ場合も分ける |
| 保存されるが別日に利用されない | 次の会話があったか、復習する理由やタイミング、操作の負担を確認。理由が出るまで通知機能を先行実装しない |
| 継続するが購入されない | 無料で十分か、有料追加枠の価値と価格が合っているかを確認。既存データの復習を課金で遮断しない |
| 購入されるが利益が出ない | 無料分を含むAPI費、固定費、集客費、紹介料、支援時間を見て枠や獲得方法を調整 |

指標は操作回数だけでなく人数で集計する。初回実利用は本人の一言の翻訳成功、別日実利用は初回翌日〜7日後に新しい翻訳・追加またはドリル回答があることとし、ページ表示だけの再訪と区別する。ゲストは端末単位の重複が残るため、真の人数と断定しない。QA・開発者・身内テストは分離する。

自発追加や現場で言えたことは操作ログだけで断定できず、連絡了承者の短い本人確認を併用する。個人のフレーズ本文の共有や事例公開は別途本人の許可を得る。

運営利益は「売上 − 全利用者のAPI費 − 決済手数料 − サーバー/DB/ドメイン等固定費 − 集客/紹介費」で追い、本人/Codex運用の時間・費用も別記して、拡大時に隠れた赤字にならないか確認する。正式な会計利益や税引後手取りとは区別する。必要有料人数は、価格・1人あたり原価・固定費が実測できてから算出する。

| マカオ・香港 | 実際に普通話を使う相手・場面か、読み上げとピンインが用途に合うか | 中国語は普通話中心と説明し、広東語対応とは案内しない |
| 台湾 | 簡体字の表示が利用の妨げになるか、普通話の語彙・発音が意図に合うか | 繁体字選択・台湾向け表現最適化を実装済みとしない |
| 英語を生活で使う地域 | 現地の相手へ意味・丁寧さが合うか、音声入力・読み上げが使えるか | 米語設定と地域別の言い方を区別する |

国だけで利用言語を決めつけず、本人が使う相手と言語で判定する。全地域の確認が揃うまで待つ必要はないが、未確認地域を動作確認済みとして募集しない。Webからの翻訳はサーバー経由なので、外部翻訳サイトの直接接続可否だけでPhrabitの動作を断定しない。

### 月3,000円の扱いと設定案

本番・Preview・開発者テスト・再生成・解説・高精度音声のPhrabit分を合算する。API契約の固定料金と税も含め、Vercel・DB・ドメイン・広告費は別管理とする。既に使った今月分を含む上限で、新たに3,000円追加できる意味ではない。9月7日現在、当月の実請求・契約プラン・他アプリとの課金共有は未確認。

運用目安は合計1,500円で確認、2,100円で新たな配信拡大と任意の大量APIテストを保留、2,400円で有料生成停止の判断。残り600円は請求反映の遅れ・税・為替の余裕とする。これは設定案であり、自動通知・停止を設定済みではなく、超過しない保証にもならない。

| 提供元 / 現在の用途 | 用意した設定手順 | 未確認事項 |
|---|---|---|
| Gemini / 品質訳・調整・解説・例文 | Phrabitの課金プロジェクトを照合し、単一プロジェクト・Gemini API対象のSpend capの利用可否を確認。通知用budgetと停止用capを区別 | 対象プロジェクト、今月分、無料/有料区分、設定可能額・機能 |
| DeepL / 通常訳 | Account → API Keys & Limitsで契約と現在利用量を確認。利用可能なら契約Cost ControlまたはPhrabitキーの文字数上限を設定 | 現契約の固定料金、従量単価、共有キーの有無 |
| Azure / 速度訳・通常訳失敗時 | 対象TranslatorリソースのSKU・使用量を確認し、Cost Managementの通知を用意。通知だけを強制停止として扱わない | 無料枠/有料SKU、Phrabit専用か、停止可能な単位 |
| OpenAI / 高精度音声入力・読み上げ | Phrabit Project → Limits → Spendで月額とEnforce a hard limitを確認。組織全体で他アプリを止めない | 課金プロジェクト、今月分、通貨、共有利用、既存上限 |

各社の上限は合計が2,400円相当以内になるよう、当月の既使用額と固定料金を確認後に割り当てる。外貨額は設定時の換算根拠と税を記録する。固定料金だけで収まらない場合は契約変更案を本人へ提示し、黙って解約・更新しない。DeepL停止後にAzureへ切り替わる費用、停止エラーの再試行も考慮する。月額API上限を利用者一人あたりの日次回数へ機械的に置き換えない。

設定時の記録欄：`提供元 / 課金対象名 / Phrabit専用か / 請求期間 / 既使用額 / 固定料金 / 上限と通貨 / 通知のみor停止 / 設定確認日時`。キー値や決済情報は記録しない。実請求の確認前に「1人あたり何円」「何人まで使える」を確定しない。既存イベントはトークン数・音声出力時間を網羅しておらず、リクエスト件数だけから正確な費用は算出できない。

公式資料を2026-09-07確認：Googleの[Spend cap（Preview）](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps)は対象サービス・プロジェクト単位。DeepLの[Cost Control](https://developers.deepl.com/docs/best-practices/cost-control)は到達後の処理を停止。Azureの[Budget](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/tutorial-acm-create-budgets)はそれ単独では利用を停止しない。OpenAIの[Spend limits](https://developers.openai.com/api/docs/guides/spend-limits)は強制停止設定があるが伝播は即時ではなく超過の可能性がある。各アカウントに設定済みであることとは区別する。

### 紹介先への依頼と7日間

紹介候補と公開窓口は `segment-marketing-experiment-2026-07.md`、そのまま確認できる依頼文は `beachhead-outreach-templates.md` の9月7日節に用意した。英中それぞれ最初に2件の紹介先へ打診する作業目標。未確認の窓口は確認してから送信する。本人の宛先・文面承認後に送信し、紹介先には教材作成・毎日の督促・個人情報リストの提供を依頼しない。

実利用者は最初の30人（英中各15人を目安）を目指すが、人数が揃うのを待たず各人の初回利用日から観察する。1人ずつ面談を積み重ねる方式には戻さず、紹介先の既存案内・コミュニティで一度共有してもらう。

| タイミング | 利用者への案内 | 運営が見ること |
|---|---|---|
| 初回 | 「最近、現地で言えなかった一言を入れて、覚えたいと思ったら追加してください」 | 流入→翻訳成功→追加。不要な追加やドリルを義務にしない |
| 初回後 | 任意でその一言のドリルを案内 | 操作テストとして促した回答と自然な利用を分ける |
| 1〜6日後 | 毎日の督促はせず、生活で必要なときに利用 | 別日の回答と、新しい会話後の追加。期間途中で案内や価格を大きく変えない |

記録単位は `紹介元ref / 対象言語 / 初回利用日 / 訪問者 / 翻訳成功者 / 追加成功者 / 別日の回答者 / 別日の追加者 / 自発追加の本人確認 / 実会話で使えた本人確認 / 不具合 / API実費`。人数とイベント回数を分ける。`translation_drill_save`のsuccess=trueを追加に数え、sync_failedは同期課題として別記。ゲストの識別は同一ブラウザ単位で、別端末を同一人物と断定しない。テスト用ref、開発者・身内の検証操作を獲得成果から除外する。refは紹介元を示すだけで、本人の所在地や学習言語を自動設定するものではない。

判定は両言語で同じ基準にする。初回利用者30人中、7日以内の別日利用10人を仮目安として維持する。繰り返す生活場面から自発追加が複数人で出れば拡大候補。訪問がないなら紹介導線、翻訳後に追加されないなら保存価値・翻訳品質、追加後に別日利用がないなら復習の理由と再発場面を確認する。7日経過していない人は7日指標の分母から外し、母数不足・計測欠損を需要ゼロと扱わない。件数差だけで片方の言語を打ち切らない。

- 高精度/仕事モードの価値確認

確認する問い:

- 何に対して払うのか
- 月額か買い切りか
- 個人課金か会社経費か
- ポーカー層と業務層で価格許容が違うか

根拠:

- `docs/roadmap-2026-2028.md`
- `docs/open-questions.md`
- `docs/translation-provider-evaluation.md`

## Phase 4: 隣接セグメント拡張

目的:

最初に勝った利用場面と同じ反復トリガーを持つ隣接セグメントへ広げる。

候補:

- 海外生活・ワーホリ・留学
- オンライン語学レッスン・言語交換
- 中国出張・駐在・帯同家族
- 接客・外国人スタッフ対応
- 外国人の恋人・配偶者・友人・同僚との継続会話
- 同じ国・地域への反復旅行

主要タスク:

- 勝ちセグメントと同じ獲得ループを隣接層へ再現する
- セグメント別の課題文と利用行動を比較する
- 支払い意思と利用頻度を比較する
- 必要な場合だけ業務利用時の保存・機密・音声入力の許容を確認する

根拠:

- `docs/crowdworks-interview-recruitment.md`
- `docs/user-segments.md`
- `docs/problem-statements.md`

## Phase 5: 収益拡大

- 専門用語辞書
- STT強化
- 言語ペア拡張
- チーム/法人利用

注意:
